# 研究方向索引

本仓库围绕 **AI+动物** 组织，分成两个方向：

| 编号 | 方向 | 定位 | 收录判定 |
| --- | --- | --- | --- |
| 01 | [AI+动物](01-ai-for-animals/) | **研究对象是动物**的工作 | 主实验跑在**动物数据集**上 |
| 02 | [可迁移基础方法](02-foundations/) | 通用方法，**可迁移到动物任务** | 主实验跑在 COCO / ImageNet / Kinetics 等**通用基准**上 |

两个方向内部结构一致：

```text
<方向>/
├── README.md            # 方向简介 + 完整任务清单
├── papers/<任务>/<年份>.md   # 论文，按任务分子目录，按年份分文件
├── surveys/<年份>.md         # 综述，放在方向这一层（通常横跨多个任务）
└── datasets/<年份>.md        # 数据集
```

## 为什么要分成两个方向

因为「这篇算不算动物相关」如果只靠感觉判断，十个人会给出三种答案，最后必然出现同一篇论文两边都收、或者两边都不收。

所以判定标准定成**可机械执行**的一条：**看论文的主实验跑在什么数据集上**。

- 用 Animal Kingdom、AP-10K、LoTE-Animal 等 → `01-ai-for-animals`
- 用 COCO、ImageNet、Kinetics、MOT17 等 → `02-foundations`

两边都做的（比如通用检测器在动物数据集上评测）：**按主实验归到一边**，另一边的 README 里提一句即可，不要重复收录。

## 任务子目录的创建规则

**有内容了才创建目录，不要预先建空目录。**

空目录比没有目录更糟——新人点进去一片空白，不知道该往哪放，也判断不出这个方向是不是没人维护。
完整的任务清单写在两个方向的 README 里，新论文来的时候对照清单找位置，有需要再建目录。

## 新增方向

先开 [Issue](../.github/ISSUE_TEMPLATE/new-direction.yml) 讨论，确认后再建目录。
**新方向取下一个可用编号**（当前是 `03`），不要插空号或重排已有编号——重排会让所有人的本地分支和已有链接全部失效。

步骤见 [CONTRIBUTING.md](../CONTRIBUTING.md#新增一个研究方向整个大方向)。
